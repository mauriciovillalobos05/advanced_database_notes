# ORM and Migrations Notes

## ORM (Object Relational Mapper)

### What is an ORM?
An ORM allows developers to interact with a database using programming language objects instead of writing raw SQL.

Example:

```python
session.query(User).all()
```

instead of:

```sql
SELECT * FROM users;
```

---

## Benefits of ORM

- Cleaner and more readable code
- Reduces repetitive SQL
- Database portability
- Easier relationships and joins
- Helps prevent SQL injection
- Faster backend development

---

## Common ORM Concepts

### Model
Represents a database table.

```python
class User(Base):
    __tablename__ = "users"
```

---

### Column
Represents a table column.

```python
username = Column(String(50))
```

---

### Session
Handles transactions and communication with the database.

```python
session.add(user)
session.commit()
```

---

### CRUD Operations

#### Create

```python
session.add(user)
session.commit()
```

#### Read

```python
session.query(User).all()
```

#### Update

```python
user.name = "Mauricio"
session.commit()
```

#### Delete

```python
session.delete(user)
session.commit()
```

---

## Relationships

Relationships connect tables together.

Example:
- One user can have many tasks

```python
tasks = relationship("Task")
```

Benefits:
- Easier joins
- Cleaner code
- Better navigation between related data

---

# Migrations

## What are Migrations?

Migrations are version-controlled database schema changes.

They allow developers to:
- create tables
- modify columns
- add constraints
- rollback changes safely

---

## Why Use Migrations?

- Keep database schema synchronized
- Track schema history
- Support team collaboration
- Enable safe deployments
- Allow rollback of mistakes

---

## Alembic

Alembic is the migration tool commonly used with SQLAlchemy.

---

## Common Migration Commands

### Create Migration

```bash
alembic revision --autogenerate -m "message"
```

---

### Apply Migration

```bash
alembic upgrade head
```

---

### Rollback Migration

```bash
alembic downgrade -1
```

---

## Upgrade vs Downgrade

### upgrade()
Applies schema changes.

Example:
- add column
- create table

---

### downgrade()
Reverts schema changes.

Example:
- remove column
- drop table

---

## Important Notes

- Always review autogenerated migrations manually
- Never trust autogenerate blindly
- Rollback is important for production safety
- Adding NOT NULL columns may require defaults

Example:

```python
server_default='medium'
```

---

# Summary

ORM:
- simplifies database interaction
- maps tables to objects
- improves developer productivity

Migrations:
- manage schema changes
- keep DB versions consistent
- support rollback and deployment safety
