# Session – 2026-05-19

## Topics covered
- Conditional Aggregation: Wrapping conditional CASE statements inside SUM and COUNT functions to bucket operational metrics (like task statuses) during a single table scan.

- Advanced Distribution Metrics: Utilizing Oracle’s PERCENTILE_CONT(0.5) to track median resolution times, protecting analytical reports from being skewed by extreme outliers.

- High-Fidelity Operational Reporting: Designing multi-layered triage metrics that combine chronological delays (days_overdue) with task priority strings to assign actionable severity risk tiers.

- Report Presentation Mechanics: Employing a CTE + UNION ALL architectural pattern to cleanly merge granular, row-level ledger details with aggregated category summary blocks in a unified schema output.

- Data Type and Algebraic Sanitization: Correcting catastrophic type-conversion traps (e.g., performing string/date multiplication) by normalizing text vectors into numeric scalar weights and dates into relative integer offsets.

## What I understood
- IDs are Labels, Not Numbers: Running mathematical aggregates like AVG() on primary keys or identifiers yields zero business value and introduces severe analytical bias toward newer records.

- Raw Volume is a Vanity Metric: Tracking flat totals (like blind assignment counts) masks true productivity and capacity. To measure true value delivered, outputs must be filtered by execution status and weighted by complexity or priority.

- The Power of the Dual-Stage CTE: Breaking messy date transformations, text mappings, and initial counts into modular, sequential CTE steps prevents code duplication, avoids division-by-zero crashes, and makes downstream math exceptionally clean.

- Normalizing for Time Off: Evaluating personal performance by dividing a weighted output score by unique active completion days (COUNT(DISTINCT TRUNC(completed_at))) creates a fair baseline that doesn't penalize employees for taking planned leave or vacations.

- Temporal Inversion Fixing: When creating an automated Urgency Index, deadlines must be calculated as a relative timeline window (due_date - SYSDATE) and subtracted from a scaled priority tier to ensure overdue emergencies naturally float to the absolute top of the queue.
