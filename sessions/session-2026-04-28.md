## What I understood
- Objects must be created in a specific order to satisfy dependencies:
  tables first, then constraints, then views and PL/SQL code.
  Skipping this order causes foreign key or compilation errors.

- Circular FK dependencies are solved by creating tables without FK constraints first,
  then adding them afterward with `ALTER TABLE ... ADD CONSTRAINT`.

- `DBMS_METADATA` only exports DDL, not data. It is the right tool when you only have
  SQL access. `expdp` is faster and exports data too, but requires DBA-level OS access.

- An empty result from a `USER_DEPENDENCIES` query does not mean something is broken —
  it just means the schema has no views, procedures, or packages referencing the tables,
  which is normal for a data-only schema.
